???+ abstract "⚡ Quick Reference"
    **Function:** `add_two_to_alternate_elements(t: tuple) -> tuple`

    **Core idea:** Use `enumerate` to get each index, add 2 when the index is even, wrap back in `tuple()`.

    ```python
    def add_two_to_alternate_elements(t):
        return tuple(x + 2 if i % 2 == 0 else x for i, x in enumerate(t))
    ```

    **Key rules:**
    - Even indices (0, 2, 4, ...): add 2
    - Odd indices: leave unchanged
    - Return a `tuple`, not a list

---

## Problem Statement

!!! note "Problem"
    Write a function `add_two_to_alternate_elements(t)` that takes a tuple of integers and returns a new tuple where `2` is added to every element at an even index. Elements at odd indices are unchanged. The tuple always has at least one element.

## Understanding the problem

Trace `(1, 2, 3, 4, 5)`:

| Index | Value | Even index? | Result |
|-------|-------|-------------|--------|
| 0 | 1 | ✅ | `1 + 2 = 3` |
| 1 | 2 | ✗ | `2` |
| 2 | 3 | ✅ | `3 + 2 = 5` |
| 3 | 4 | ✗ | `4` |
| 4 | 5 | ✅ | `5 + 2 = 7` |

Output: `(3, 2, 5, 4, 7)`

!!! insight "enumerate() gives both index and value together"
    Without `enumerate`, you'd need a separate counter or use `range(len(t))` to track the index. `enumerate(t)` yields `(index, value)` pairs directly, making `i % 2 == 0` the natural parity check.

---

## Solution approaches

=== "Explanatory"

    ```python
    def add_two_to_alternate_elements(t: tuple) -> tuple:
        result = []
        for i, x in enumerate(t):
            if i % 2 == 0:       # even index: add 2
                result.append(x + 2)
            else:                # odd index: keep as-is
                result.append(x)
        return tuple(result)
    ```

=== "Pythonic"

    ```python
    def add_two_to_alternate_elements(t: tuple) -> tuple:
        return tuple(x + 2 if i % 2 == 0 else x for i, x in enumerate(t))
    ```

=== "Using lambda"

    ```python
    add_two_to_alternate_elements = lambda t: tuple(
        x + 2 if i % 2 == 0 else x for i, x in enumerate(t)
    )
    ```

## Key takeaways

<div class="pb-cards">

<div class="pb-card">
<div class="pb-card-num">01</div>
<h4><code>enumerate()</code> for index-aware iteration</h4>
<p><code>for i, x in enumerate(t)</code> gives the index <code>i</code> and value <code>x</code> simultaneously. It's the idiomatic Python alternative to <code>for i in range(len(t))</code> followed by <code>t[i]</code>.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">02</div>
<h4>Generator expression inside <code>tuple()</code></h4>
<p><code>tuple(expr for ...)</code> builds a tuple directly from a generator -- no intermediate list needed. The parentheses of <code>tuple()</code> wrap the generator, so no extra brackets are required.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">03</div>
<h4>Tuples are immutable -- always return a new one</h4>
<p>You cannot modify a tuple in place. The correct approach is to build a new sequence (list or generator) with the changes applied, then wrap it in <code>tuple()</code> to return the right type.</p>
</div>
