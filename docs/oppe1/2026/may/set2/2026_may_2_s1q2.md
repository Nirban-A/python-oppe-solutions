???+ abstract "⚡ Quick Reference"
    **Function:** `train_ticket(passenger: dict, available_seats: int) -> str`

    **Core idea:** Four rules applied in strict priority order -- each is an early return.

    ```python
    def train_ticket(passenger, available_seats):
        if not passenger["has_id"]:    return "ID Required"
        if available_seats <= 0:       return "Waiting List"
        if passenger["age"] >= 60:     return "Priority Booking"
        return "Ticket Confirmed"
    ```

    **Key rules (in order):**
    - No ID → `"ID Required"` (checked first, overrides everything)
    - No seats → `"Waiting List"`
    - Age >= 60 → `"Priority Booking"`
    - Otherwise → `"Ticket Confirmed"`

## Problem Statement

!!! note "Problem"
    Write a function `train_ticket(passenger, available_seats)` where `passenger` is a dict with keys `"age"` and `"has_id"`. Apply the four booking rules in the given order and return the appropriate status string.

## Understanding the problem

The rules form a strict priority chain -- each condition is only checked if all previous ones passed:

```
has_id?  ──No──▶  "ID Required"
   │
  Yes
   │
seats > 0?  ──No──▶  "Waiting List"
   │
  Yes
   │
age >= 60?  ──Yes──▶  "Priority Booking"
   │
   No
   │
"Ticket Confirmed"
```

!!! insight "Rule ordering determines the result for edge cases"
    A senior citizen without an ID still gets `"ID Required"` (not `"Priority Booking"`) because the ID check comes first. A senior citizen with an ID but no seats gets `"Waiting List"`. The order in the problem statement is the exact order the checks must be coded.

**Tracing the three given examples:**

| Age | has_id | Seats | ID check | Seats check | Age check | Result |
|-----|--------|-------|----------|-------------|-----------|--------|
| 65 | True | 5 | pass | pass | 65 >= 60 ✅ | `"Priority Booking"` |
| 30 | False | 5 | fails ❌ | -- | -- | `"ID Required"` |
| 22 | True | 0 | pass | 0 <= 0 ❌ | -- | `"Waiting List"` |

## Solution approaches

=== "Explanatory"

    ```python
    def train_ticket(passenger: dict, available_seats: int) -> str:
        # Rule 1: ID is mandatory -- checked before anything else
        if not passenger["has_id"]:
            return "ID Required"

        # Rule 2: No point booking if no seats exist
        if available_seats <= 0:
            return "Waiting List"

        # Rule 3: Senior citizens get priority when seats are available
        if passenger["age"] >= 60:
            return "Priority Booking"

        # Rule 4: All other valid passengers
        return "Ticket Confirmed"
    ```

=== "Pythonic"

    ```python
    def train_ticket(passenger: dict, available_seats: int) -> str:
        checks = [
            (not passenger["has_id"],      "ID Required"),
            (available_seats <= 0,         "Waiting List"),
            (passenger["age"] >= 60,       "Priority Booking"),
        ]
        for condition, status in checks:
            if condition:
                return status
        return "Ticket Confirmed"
    ```

=== "Using lambda"

    ```python
    def train_ticket(passenger: dict, available_seats: int) -> str:
        rules = [
            (lambda p, s: not p["has_id"],    "ID Required"),
            (lambda p, s: s <= 0,             "Waiting List"),
            (lambda p, s: p["age"] >= 60,     "Priority Booking"),
        ]
        for condition, status in rules:
            if condition(passenger, available_seats):
                return status
        return "Ticket Confirmed"
    ```

## Key takeaways

<div class="pb-cards">

<div class="pb-card">
<div class="pb-card-num">01</div>
<h4>Early returns enforce priority</h4>
<p>Returning immediately when a condition is met means later checks never run. This is cleaner than nested <code>if/else</code> and maps directly to the "apply rules in order" problem statement.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">02</div>
<h4>Accessing dict values with <code>dict["key"]</code></h4>
<p><code>passenger["has_id"]</code> and <code>passenger["age"]</code> pull values from the dict by key. Since the problem guarantees both keys exist, direct access is safe and more readable than <code>.get()</code> with a default.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">03</div>
<h4>List of (condition, result) pairs for rule tables</h4>
<p>The Pythonic approach stores each rule as a <code>(condition, status)</code> tuple in a list, then iterates until one matches. This pattern scales cleanly when the number of rules grows -- adding a new rule is just one more line in the list.</p>
</div>
