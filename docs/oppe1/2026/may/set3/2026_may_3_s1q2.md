???+ abstract "⚡ Quick Reference"
    **Function:** `has_common_integer(a: set, b: set) -> bool`

    **Core idea:** Set intersection -- non-empty means at least one common element exists.

    ```python
    def has_common_integer(a, b):
        return bool(a & b)
    ```

    **Key rules:**
    - `a & b` is the intersection of the two sets
    - An empty set is falsy; a non-empty set is truthy
    - `bool()` converts the result to `True` or `False`

## Understanding the problem

Set intersection (`&`) produces a new set containing only the elements present in both sets:

| `a` | `b` | `a & b` | Non-empty? | Result |
|-----|-----|---------|------------|--------|
| `{1,2,3}` | `{3,4,5}` | `{3}` | ✅ | `True` |
| `{10,20}` | `{30,40}` | `{}` | ✗ | `False` |
| `{7,8}` | `{8,9}` | `{8}` | ✅ | `True` |

!!! insight "Empty sets are falsy in Python"
    `bool(set())` is `False`; `bool({3})` is `True`. So `bool(a & b)` converts the intersection directly to the answer -- no need to check `len()` or compare to `set()`.

!!! insight "Two equivalent alternatives"
    `a.isdisjoint(b)` returns `True` when sets have NO common elements. So `not a.isdisjoint(b)` also works and is slightly more readable in plain English: "they are not disjoint". Both approaches are O(min(len(a), len(b))).

## Solution approaches

=== "Explanatory"

    ```python
    def has_common_integer(a: set, b: set) -> bool:
        common = a & b          # intersection: elements in both sets
        return len(common) > 0  # True if at least one common element
    ```

=== "Pythonic"

    ```python
    def has_common_integer(a: set, b: set) -> bool:
        return bool(a & b)      # empty set is falsy, non-empty is truthy
    ```

=== "Using lambda"

    ```python
    has_common_integer = lambda a, b: not a.isdisjoint(b)
    ```

## Key takeaways

<div class="pb-cards">

<div class="pb-card">
<div class="pb-card-num">01</div>
<h4>Set intersection: <code>a & b</code> or <code>a.intersection(b)</code></h4>
<p>Both forms produce the set of elements common to <code>a</code> and <code>b</code>. The <code>&</code> operator is more concise; <code>.intersection()</code> also accepts any iterable, not just sets.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">02</div>
<h4>Truthiness of sets</h4>
<p>An empty set <code>set()</code> is falsy; any non-empty set is truthy. Wrapping in <code>bool()</code> converts the intersection result directly to the answer -- a common idiom for "does this collection have anything?"</p>
</div>

<div class="pb-card">
<div class="pb-card-num">03</div>
<h4><code>set.isdisjoint()</code> for the "no overlap" check</h4>
<p><code>a.isdisjoint(b)</code> returns <code>True</code> when sets share no elements. It short-circuits on the first common element found, making it efficient. Negate it (<code>not a.isdisjoint(b)</code>) to check for any overlap.</p>
</div>
