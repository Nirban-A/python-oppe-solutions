???+ abstract "⚡ Quick Reference"
    **Type:** Full I/O problem

    **Core idea:** Read all `(int, string)` pairs, then use `max()` with `key=len` on the string to find the longest. `max()` returns the first maximum by default.

    ```python
    n = int(input())
    entries = [input().split() for _ in range(n)]
    best = max(entries, key=lambda e: len(e[1]))
    print(best[0])
    print(best[1])
    ```

    **Key rules:**
    - First occurrence wins on tie -- `max()` returns the first max it encounters
    - Output: integer on line 1, string on line 2
    - No type conversion needed for the integer in the output (it stays a string from `split()`)

---

## Problem Statement

!!! note "Problem"
    Read `n` entries, each a pair of an integer and a string. Print the integer and string of the entry whose string is longest. If multiple entries tie, print the one that appears first in the input.

## Understanding the problem

String lengths for the first example:

| Integer | String | Length |
|---------|--------|--------|
| 1 | `apple` | 5 |
| 2 | `banana` | 6 ← max |
| 3 | `kiwi` | 4 |
| 4 | `mango` | 5 |

Output: integer `2`, string `banana`.

!!! insight "max() with key= picks the first maximum"
    Python's `max()` scans left to right and returns the first element that achieves the maximum key value. When two strings tie in length, the one that appears earlier in the list is returned -- exactly the tie-breaking rule required here.

!!! insight "No need to convert the integer for output"
    `input().split()` produces strings. Since the integer is printed as-is (not used in arithmetic), it can stay as a string: `print(best[0])` works without `int()`. Converting to `int` and back is unnecessary here.

## Solution approaches

=== "Explanatory"

    ```python
    n = int(input())
    entries = []
    for _ in range(n):
        parts = input().split()   # [integer_str, word]
        entries.append(parts)

    # max() with key picks the pair whose string (index 1) is longest
    best = max(entries, key=lambda e: len(e[1]))
    print(best[0])   # the integer
    print(best[1])   # the string
    ```

=== "Pythonic"

    ```python
    n = int(input())
    entries = [input().split() for _ in range(n)]
    best = max(entries, key=lambda e: len(e[1]))
    print(best[0])
    print(best[1])
    ```

=== "Using lambda"

    ```python
    n = int(input())
    entries = [input().split() for _ in range(n)]
    print('\n'.join(max(entries, key=lambda e: len(e[1]))))
    ```

## Key takeaways

<div class="pb-cards">

<div class="pb-card">
<div class="pb-card-num">01</div>
<h4><code>max(iterable, key=...)</code> for custom comparison</h4>
<p>The <code>key</code> parameter tells <code>max()</code> what to measure. Here <code>key=lambda e: len(e[1])</code> measures the length of the string in each pair. <code>max()</code> then returns the whole pair, not just the key value.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">02</div>
<h4>First-maximum tie-breaking is built in</h4>
<p><code>max()</code> returns the first element that achieves the maximum during a left-to-right scan. No extra logic is needed to handle ties -- the natural scanning order gives first-occurrence priority automatically.</p>
</div>

<div class="pb-card">
<div class="pb-card-num">03</div>
<h4>Keep pairs together as a list of lists</h4>
<p>Storing each entry as <code>[integer_str, word]</code> keeps the associated values together throughout. When <code>max()</code> returns the winning pair, both the integer and the string are immediately accessible by index.</p>
</div>
